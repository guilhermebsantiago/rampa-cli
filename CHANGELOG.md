# Changelog

Changes to `rampa-cli`, newest first. Each released version has a `## [x.y.z] - date` section; the release workflow publishes that section as the version's GitHub release notes, and it stops before publishing when the section is missing ([RELEASING.md](RELEASING.md)). Changes not released yet go under Unreleased.

## Unreleased

- **The 1.1.1 second pass works on OpenAI and other models that reason first.** Its one-word answers had a budget of 8 output tokens: OpenAI refused the request ("Invalid 'max_output_tokens' … Expected a value >= 16"), so on `openai:gpt-6-luna` 4 pages of `rampa eval` ended with an error, and a model that reasons by default would have spent any small budget thinking and answered nothing (gpt-6-luna, asked for one word with 16 tokens, used all 16 on reasoning). The budget is now 1,024 tokens; the answer's first word is still the one read. Ollama, which answers through its native API with 2 tokens, is unchanged.
- **Precision on real pages: two fixes from the fifth real-page study's dev half, every number in-sample or counted** ([notes](docs/studies/notes-precision-p1p2.md)). The [notes after round 5](docs/studies/notes-precision-round5.md) traced 8 of the dev half's 8 false findings to two 2.4.4 mechanisms and 6 denied true 1.1.1 findings to the second pass, and measured offline the two changes below; their rules were frozen before a replay of the 96 recorded pages of the second to fifth studies confirmed them:
  - **A card's heading completes a generic link text (WCAG technique H80), and a disclosure toggle is no link to judge.** A "Leia mais" in a news or course card built of `div`s (a heading, a blurb, the link) had no sentence of its own, so a generic claim on it was a finding. The heading of its card now counts as what can complete it: the nearest heading before the link, when the two share an element at most two levels above the link holding at most 300 characters of text; the prompt says so on those links ("Heading of the card the link sits in"), and every other 2.4.4 prompt stays the same. A generic link that leads nowhere (`#`, no `href`, a script) with a list after it in its own list item opens a submenu, and no generic claim rests on it either. Such a link is no longer judged first when a page has more links than the cap. pucrs.br's 7 false "Leia mais" and "Saiba mais" findings and horniman.ac.uk's false "More" are gone, and infomoney's uncertain "Veja mais"; no true finding was lost. A link under a small section whose heading says nothing ("Section 2") is now a suggestion too ([criteria](docs/criteria.md#244-link-purpose-in-context)).
  - **Identical 1.1.1 claims on one page are confirmed together.** The second pass asked each copy of a claim on its own, so www.hering.com.br's seven payment logos with `alt="payment"` became one finding and six suggestions, all seven true. Claims the pass was asked about on one page with the same alternative (case, accents and spaces ignored) and the same verdict now form a group, and one it confirms confirms the ones it denied; a claim with no cached answer offline or a failed call keeps its outcome. JSON says so in `confirmation.identical` (and the schema), the terminal and Markdown in "confirmed by a second pass on an identical claim on this page". It added hering's 6 true findings and 2 false ones whose twins were already false findings (puc-rio.br, cobasi.com.br), and lost none.
  - **Measured on the replay:** the fifth study's dev half 31 true / 8 false (0.79) to 37 / 0 (1.00, 0.91–1.00), in-sample; the second to fourth studies 95 / 16 (0.86) to 95 / 18 (0.84), in-sample; the two together 126 / 24 (0.84) to 132 / 18 (0.88, 0.82–0.92), in-sample. The fifth study's test half, held out from these fixes' design but counted once since, is unchanged at 20 / 4 (0.83): it had neither mechanism, so it measures neither fix. No finding is new; the replay asked the model 72 new 2.4.4 questions, those of the new prompt line and the cap's new order. The round-5 notes measured 7 true findings for the 1.1.1 rule; the seventh came from an earlier probe's run and never reaches the shipped second pass. On the W3C ACT cases, 1.1.1 and 2.4.4 give the same record for every page and pair as before. The demo's recordings replay with no miss and the same findings, and were not recorded again. Labels are two Claude judges', not people's.

- **Precision on real pages: four fixes for the bursts the fourth real-page study left, every number in-sample until a fifth round on fresh pages** ([notes](docs/studies/notes-precision-fixes.md)). The [fourth study](docs/studies/real-pages-2026-10-round4.md), pre-registered and on pages no fix had seen, measured 0.54 on its test half, 0.19 on its dev half and 0.29 pooled. Over the second to fourth studies, 95 findings were true and 129 false, and 108 of the false ones sat on three pages. What changed, with its effect on the 72 recorded pages of those studies, replayed with the rules frozen first (so in-sample: the pages were read to choose the fixes; labels by two Claude judges, not people):
  - **Links that share a text tell apart by the list items they are nested in (WCAG technique H81).** The 2.4.4 shared-text fact now also compares the text of each list item a link is nested in, outside the nested list, and the name a list, menu or group around it has of its own. www.toolstation.com's footer menu, kept for screen readers, nests each department again under "Deals" and "Sale & Clearance": 50 false "shared by N links" findings, none left. On the 72 pages no other finding changed, and all 21 true shared-text findings stay. Comparing the landmark a link sits in as well was tried and not adopted: it cost one of the 21.
  - **A page with no style at all and the browser's default body look is read as unstyled.** A site that serves an automated browser a stripped page (no stylesheet linked, none in a `style` element) whose body text has the default look (16 px Times, black) and that has at least 150 elements is loaded once more and, if unchanged, judged only as suggestions with nothing measured from pixels, as a page whose stylesheets failed already was; museudoamanha.org.br's 8 false 3.1.2 findings. A recording made before is read from its body look (www.ufpe.br's 50 false 2.4.4 findings in the third study, which the earlier guard could not catch from its recording). A stylesheet link whose address is the page itself is no longer counted as a stylesheet, which had made www.thejournal.ie read as unstyled. On the 93 recorded snapshots (the studies' and the demo's), only those two pages read as unstyled; a W3C ACT test case or a small fixture written without CSS is read as it is.
  - **The 1.1.1 second pass needs a probability of 0.99, not 0.9.** The fourth study pre-registered the cut as a secondary; the replay, with every second-pass probability read back, found 5 false, 2 uncertain and no true finding between 0.9 and 0.99.
  - **2.4.2 and 3.3.2 fails with no checked fact behind them are suggestions.** Neither had a true finding in four studies. A 2.4.2 fail stays a finding only for a generic title, an address or a file name, or a title identical to another page of the site; a 3.3.2 fail only when the field's label was measured as unseen or nothing visible sits beside the field.
  - **Measured, in-sample:** default-threshold judgment findings 95 true / 129 false (0.42, 0.36–0.49) to 95 / 16 (0.86, 0.78–0.91; page bootstrap 0.78–0.92), no true finding lost and none new; per study, the second 0.91 before and after, the third 0.39 to 0.85, the fourth 0.29 to 0.82 (its test half 0.54 to 0.78, its dev half 0.19 to 0.87). Counting each group of 6 or more findings of one claim on one page as one, 0.76 to 0.83. Suggestions on those pages went from 235 to 306. On the W3C ACT cases, 1.1.1 keeps precision and recall 1.00; the 3.3.2 pairs go from 14 of 14 to 13 of 14 (one `label-hidden` page has text beside its fields, so its claims are suggestions); 2.4.2's ACT 2779a5 goes from precision 0.50 to 1.00 (its passed pages' "Title of the page." claims are suggestions) and c4a8a4 from recall 1.00 to 0.00 (its three failed examples are mismatches, the model's reading); every other set of the demo's recorded evaluation, recorded again, keeps its numbers. These fixes were chosen on the pages they are measured on, and the remaining risk is the next page with a burst cause not seen yet: a fifth round on fresh pages is what would measure them.

- **A burst of near-identical findings on one page is shown once, as a group to review together.** Most false findings on real pages came from one page repeating one claim: 50 2.4.4 "shared by N links" findings from one hidden menu on www.toolstation.com, 50 on www.ufpe.br ([notes](docs/studies/notes-precision-check.md)). On one page and in one list, more than five findings with the same criterion, check (`ruleId`, or `judgment/<criterion>`) and claim kind (`claim`, new on judgment findings: the model's `problem`, or 1.3.2's `relation`) now form a group. The terminal, Markdown, HTML and MCP show it as one entry with the count, one example and every element with its id; SARIF as one result at the example with every member a related location, since SARIF allows several locations on a result only when one change at all of them fixes it. JSON adds `groups` (id, list, criterion, check, claim, count, member ids, example) and keeps every finding as it was; [schema/report.schema.json](schema/report.schema.json) is new, and the schema version stays 1. This changes what a person reads, not what is found or counted: every member is still a finding, the exit code, `--fail-on`, the baseline and waivers count each one, and `rampa eval` scores per element as before. It fixes none of the causes of a burst, and a group of right findings is grouped as readily as a group of wrong ones. In code scanning, a group is one alert, so the per-element alerts of a group close on the first upload with groups ([docs](docs/output-formats.md#groups-of-near-identical-findings)).
- **Precision on real pages: five changes from the [precision probe](docs/studies/notes-precision-probe.md) of 2026-10-23, every number in-sample until round 4.** The probe put every labelled finding of the three real-page studies in one table (218 default-threshold judgment findings on studies 2 and 3: 72 true, 137 false, precision 0.34, labelled by two Claude judges, not people), found that three causes held 84% of the false positives, and simulated each change on those findings before it was written. What changed, and what each did on those same findings (so an optimistic, in-sample number; the frozen rules are in the notes, and a pre-registered fourth round on fresh pages is what would confirm any of it):
  - **A page read without its stylesheets is loaded once more, and if it is still unstyled the report says so and judges nothing from it.** www.ufpe.br's theme CSS did not apply in the third study, a hidden type-ahead list of 1,628 links became visible, and 50 "ambiguous link" findings followed: 36% of the false positives. The snapshot records the stylesheets that did not apply (`reach.stylesheets`), the first note says the page was read unstyled, every judgment that rests on what is visible is listed as the model's suggestion, and contrast and label visibility are not measured from pixels. Simulated: 50 false positives gone, no true positive lost. The guard did not fire on any study page, since the capture was transient; a local page with a missing stylesheet tests it.
  - **A layer over the viewport is hidden while pixels are measured.** www.ed.ac.uk's consent backdrop, in a closed shadow root, dimmed every pixel the contrast rules measured: 15 of the third study's 23 experimental false positives on its test half. An element on top at seven or more of nine points of the viewport, out of the flow or hosting a shadow root and holding little of the page's text, is recorded (`reach.overlay`) and hidden with the fixed layers during captures.
  - **A second pass over the 1.1.1 claims that rest on the model's reading** (`core/confirm.ts`, [criteria](docs/criteria.md#111-non-text-content)). A verified fail that says an alternative describes something the image does not show, or that a functional image does not say where its link leads (right 7 times in 59 and 18 in 32 on the labelled findings), is asked again as one-word questions framed three ways, with the same picture; it is a finding only when every framing confirms it and, where the provider reports token probabilities (Ollama's native API does), the lowest probability of a confirming word is at least 0.9; otherwise it is the model's suggestion, saying what the pass answered. Simulated on the labelled findings: the three framings kept 34 of 40 true positives and 12 of 61 false positives (AUROC 0.89–0.91 per framing); with the other changes, precision 0.34 → 0.83 (0.73–0.90), 4 of 72 true positives lost. The answers are cached like judgments, so recorded pages replay offline; `--no-confirm` is the ablation for `rampa check` and `rampa eval`; a provider that answers in text only decides on the words, and an agent CLI, which cannot answer so, leaves such claims suggestions.
  - **Claims no fact supports are suggestions:** a 2.4.6 label several fields share (six findings on the studies' pages, all wrong: four "Search USPS.com" fields in four collapsed menu panels; ACT cc0f0a's Failed Example 4 becomes a suggestion), a 3.3.2 "nothing on screen" claim on a field that was collapsed, off screen or a search field (three findings, all collapsed header search boxes), and a 2.4.4 raw address that sits in a sentence (three). Simulated: 9 false positives gone, none true.
  - **Three 1.1.1 facts:** a logo that leads to the site's home page, a flag named by its language inside a language link, and an alternative whose words are all in the text next to the image (nps.gov's "Acadia banner image" on the Acadia card, an icon named "cancer icon" over the heading "Cancer"). Simulated: 19 false positives gone and 2 true positives that the version-5 description check already drops.
  - **Link destinations are read through the `undici` package, paced per origin.** Node 24's bundled undici 7 crashes the process with `assert(!this.paused)` when a server ends the connection while a response body is paused under backpressure (undici #5360, fixed in 8.4.1 and not in the 7.x line Node bundles); kcl.ac.uk did it on every load in the third study. The reader now uses undici 8's `fetch`, at most two addresses of one origin at a time, 250 ms apart.
  - **Measured, in-sample, on the studies' recorded snapshots** ([section 9 of the notes](docs/studies/notes-precision-probe.md)): study 3's dev half 0.43 → 0.83 (15 TP / 3 FP), its test half 0.24 → 0.30, where the 50 ufpe.br findings stay because the unstyled capture cannot be replayed from a recording (0.77 without that page); study 2's dev half 0.49 → 1.00 (19 / 0), its test half 0.38 → 0.77 (10 / 3); pooled 0.34 → 0.52, and 0.84 on the findings the recordings can replay, with 4 of 72 true positives lost, three of them to the second pass. On the W3C ACT cases 1.1.1 keeps precision and recall 1.00 with the second pass on and off; of the demo's recorded evaluation only cc0f0a moves, from 1 of 6 failed examples to 0, since a shared label is a suggestion now.
- **A bot check in place of the page is reported, not checked.** Sites behind bot protection often answer an automated browser with a challenge page, a captcha or a short "Access denied" page; Rampa used to check that page as if it were the site: 12 of 53 real sites in the [robustness study of 2026-10-23](docs/studies/robustness-2026-10-23.md), 9 of them failing with findings about Cloudflare's or Akamai's page and 3 passing. It now recognizes one by strong signs only (a header such as `cf-mitigated: challenge`; on a short page, a vendor's challenge script, form or frame, an Akamai reference number, a challenge title, or HTTP 403 or 429), does not read it, says in every format's headline that nothing was checked and in the first note what the site sent and what gave it away, skips the probes and the cognitive profile on it, and exits 2 with a line on stderr. JSON and the snapshot have `blocked`. Rampa never solves or gets around a bot check ([docs](docs/output-formats.md#exit-codes-and---fail-on)).
- **An error page says it is one.** A page that came with an HTTP error (a 404 page, say) is checked as before, and the first note now gives the status; JSON and the snapshot have `httpStatus`.
- **A script that masks an element no longer stops the check.** HUMAN's captcha gives its frame DOM properties of its own that read as undefined, and the collector stopped with `Cannot read properties of undefined (reading 'nodeType')`. Such an element is now left out with what it holds, and a note and `reach.masked` count it. When axe-core stops with an error on a page, the rest of the check runs, and a note gives the error (`error` in the engine results).
- **A page that reloads itself after load is read once its new document has loaded.** amazon.com answers an automated browser with a 202 page that sets a cookie and reloads; Rampa read the new document while it was still being parsed (one element, no title). A page that reloads at the same address while it is read no longer waits 10 s for its address to change.
- **A page whose `load` event never fires is read as it is when `--timeout` runs out**, with a note that what was still loading may be missing (`reach.loadTimedOutMs`), instead of failing with "did not reach load within 30000 ms". Busy news sites (UOL, Folha, Estadão) failed so in the study: an ad or a widget kept loading long after the page had arrived. A page whose document never arrives still fails, and so does `--wait-for networkidle` or `domcontentloaded` past its limit.
- **A page that could not be loaded says why in words**, without Playwright's call log ("could not be loaded (net::ERR_HTTP_RESPONSE_CODE_FAILURE): the server answered with an HTTP error (403) and an empty page, as some bot protection does with automated browsers"), and a navigation that fails because the network dropped or the connection was cut is tried once more after 2 s. The probes open their pages the same way.
- **The text-spacing probe (`--probe layout`, 1.4.12) no longer fails on custom elements that define a `style` of their own.** On youtube.com, `yt-attributed-string` gives a symbol there, and the probe stopped with `target.style.setProperty is not a function`, so 1.4.12 went unchecked. It now sets the spacing through the browser's own inline style.
- **`coga/abbreviations` reads names in camel case as names**: TikTok, AirTag, DevCon and VaiVem are no longer reported as abbreviations without an explanation. Abbreviations that end in capitals (PhD) still are.
- **The judgments' remaining weak spots, from the W3C ACT test cases, the corrupted pairs and the fresh-page study's dev pages only** ([notes](docs/studies/notes-remaining-errors.md); the held-out measurement has to come from round 3 or later). **1.1.1** (`judgment/1.1.1@5`) asks for the model's description of the image in the same language as its suggestion, the one declared for the image (its element's `lang`, else the page's), which Rampa takes to be the alternative's; and it drops a "describes something the image does not show" claim when the description and the suggestion together keep every word the alternative names; a name or a number meets them in any language. On the dev pages, the two Portuguese alternatives the model still called wrong ("Capa da edição 751", "Boletim InfoGripe") were dropped in both runs of the new prompt, with no true failure lost, while three runs of the old prompt reported the first every time (a photo the model sometimes takes for someone else came back in one run of each prompt). What dropped them was the existing check on the suggestion, because the new prompt's suggestions kept their words: the new check on the description dropped no claim on the dev pages or the ACT cases, and only tests back it. The version bump asks every 1.1.1 judgment again once, and the demo's 13 recorded answers were recorded again with the same findings. **2.4.4** finds two more kinds of fail on facts it checks. A link text that names only a file's format ("HTML", "EPUB", "PDF") with nothing in its context or its heading above that says which document, or only its download ("Download") in a table row whose header cells do not name the row's document, outside the site's menus, header and footer (ACT 5effbb recall 0.50 → 0.83, precision 1.00). And a mismatch with a part of this page that the page names (its id and its text share a word; for a heading, its section) while the link's text and context name none of it, except for links that name a region or a control (skip links, "back to top", a carousel's arrows, links to a menu, a search field or a form): the `link-mismatch` pairs went from 0 to 9 of 10, but that corruption points every link at a paragraph whose id and text both say "hours", the shape this fact checks, and the fact was written after reading it, so those 9 pairs measure the rule rather than the model and are no held-out measure. The fact reads words: a synonym or a translation of the part's name satisfies it too, and then only the model's verdict decides. A mismatch with another page stays a suggestion: on the dev pages, the specific link texts sharing no word with the page they lead to were none of them a mismatch. On the dev pages neither 2.4.4 fact holds for any link, so no dev finding changes; their guards were written after reading those pages' links, so their precision on real pages is not measured. A review of the change narrowed both facts before merging (every landmark around a link, not only the closest; a number without a unit names a document; a heading's section; skip links and links to regions or controls left out; a repeated id read at its first element), with the same numbers on the ACT cases and the dev pages. The demo's recorded evaluation (`demo/recorded/eval/ollama-gemma4-12b`) was recorded again with this code: 5effbb recall 0.50 → 0.83 and the `link-mismatch` pairs 0 → 9 of 10 (all pairs of its five criteria 29 → 38 of 47, the 9 with the caveat above); every other case kept its outcome.
- **A 4.1.3 pass clears its item to review again.** The status-message judgment (`judgment/4.1.3@2`, with `--probe status`) now asks the model to copy, on a pass, the text that appeared. Its prompt asked for empty evidence on a pass, and verification discards a pass that quotes nothing, so nearly every pass left its item for a person. The verification rule is unchanged; the version bump re-asks cached 4.1.3 judgments once.
- **Refs escape tag names.** A tag name the HTML parser takes whole but a selector misreads, such as `<x-a.b>` (`.` reads as a class) or `<foo:bar>` (`:` reads as a pseudo-class), is escaped the way ids already were: `x-a\.b`, `foo\:bar`. Before, the ref of such an element, or of anything inside it, named another element or none, so what finds an element by its ref (image and contrast captures, the probes) could miss it. The collector, the probe kit and the browser-tree reader build the same refs, and refs of ordinary tags are unchanged.
- **The demo's offline evaluation step shows real numbers.** `MODO=offline bash demo/apresentacao.sh` ran `rampa eval --offline --cache-dir demo/recorded/cache`, which found none of its judgments: that cache holds the recorded pages' judgments, and its ACT entries were from older prompts. It now reads an evaluation recorded with Gemma 4 12B, `rampa compare demo/recorded/eval/ollama-gemma4-12b`, with no browser, model or network ([demo/README.md](demo/README.md)).
- [docs/benchmark.md](docs/benchmark.md)'s generated text no longer says that findings below the threshold include judgments of link texts and headings: since the 2.4.4/2.4.6 change, a model's fail on those that no checked fact supports is a suggestion, which neither reading counts. The tables were scored again from the same results, and no number changed. `bench/run.mjs --score-only` now keeps the run's version, machine and count of tuned rules, and reads the folder's pairs without the pair pages.
- **Three checks of the cognitive profile that a model decides**, experimental and run only with `--profile cognitive` and a model: `coga/literal-language` (COGA o3p04, GAIA G02) asks about idioms, metaphors, sarcasm and jokes in headings, labels, buttons, links, instructions next to fields and error and status messages, never body prose, and gives what they mean; `coga/long-text-summary` (o3p08) asks whether text of more than 300 words starts with a short summary; `coga/error-wording` (o4p04) asks whether the error messages Rampa finds say how to put the problem right, and proposes a clearer one. Every claim must quote the page and pass the criteria's quote check, plain interface words such as "sign in" and "carrinho de compras" are never claimed, and a message with a WCAG 3.3.1 or 3.3.3 result is left to it. What they report is a suggestion to review: it never changes the exit code, not even under `--fail-on advisory`. With `--no-llm` or no model each says it did not run, and why. On their fixtures, Gemma 4 12B got 11 of 11, 7 of 8 and 8 of 8 right; they are not measured on real pages ([docs](docs/cognitive-profile.md#checks-a-model-decides-literal-language-summaries-and-error-messages)).

## [0.1.1] - 2026-10-15

Fixes found by the W3C ACT implementation report and by the dev half of the fresh-page study. Only the dev half was used to choose them; the held-out half has to be measured again on new pages.

- **1.1.1 judgments the page contradicts are dropped.** A brand glued to "logo" ("Instagramlogo") is a name, not a garbled alt; an alt that repeats its link's visible text is not "missing" anything; a linked image whose alt names the destination (its title, a part of its address, or the service a share link goes to) does say where the link leads; and an alt equal to its file name is a placeholder only when the name looks like a file name ("Lula" from `Lula.png` is a name). "img-1", "image.png", "logo" alone and an empty alt on an informative image still fail. On the dev pages, 1.1.1 precision went from 0.27 to 0.70 with no true failure lost ([notes](docs/studies/notes-111-dev-fixes.md)).
- **`rampa/link-color-only` compares a link with the text of its own block**, in the style most of it has, and does not apply where there is no such text (a menu, a list of links). On the dev pages its 10 labelled false positives are gone ([notes](docs/studies/notes-rules-dev-fixes.md)).
- **A text field's caret counts as its focus indicator** (Understanding 2.4.7), for `rampa/focus-visible` and `rampa/focus-indicator-contrast`. Buttons, links and read-only fields with no visible change are still reported.
- **A page cut at the collector's element limit says so** in every report, with the criteria whose checks did not run past the cut.
- **`rampa/placeholder-text`** keeps only phrases no page means ("Label here", "Seu rótulo aqui"); "Your label" is no longer flagged.
- **Standalone SVG and XML documents no longer stop the check.** axe-core is evaluated in the page instead of added as a `<script>`, which an SVG document has no head for. An SVG document is checked by axe-core and the rules that read the tree, and the report says what did not run on it (contrast from pixels, the probes). An XML document that the browser shows as its source tree is not checked, and the report says so, instead of checking the browser's view of the source. The snapshot records the kind of document (`document`). 13 of the W3C ACT test cases are such documents.
- **An experimental rule no longer hides an item to review.** A rule that takes over what axe-core left undecided (`resolves`; `rampa/pixel-contrast` for `color-contrast`, and the media, skip-link and link-color probe rules) now removes axe-core's item to review only when the report shows its result instead: its own item to review, a failure at the threshold in effect, or a pass at a confidence that meets it. At the default threshold an experimental rule's failure or pass leaves axe-core's item in place, with what the rule measured as its evidence. Before, the item went away and the failure stayed below the threshold, so the default output showed nothing (ACT afw4f7).
- The GitHub Action installs `rampa-cli` from npm, at the version in its own `package.json`, so `uses: guilhermebsantiago/rampa-cli@v0.1.0` runs exactly the published 0.1.0. It builds from its checkout only when that version is not on npm, or when `from-source: true` asks for it.
- `rampa init` pins the action in the workflow it writes to this release's tag instead of `@main`.
- Releases are published to npm from GitHub Actions with trusted publishing (OIDC) and provenance.

## [0.1.0] - 2026-10-15

Rampa's first release on npm, as **`rampa-cli`**. The command it installs is `rampa`.

```sh
npm install --global rampa-cli      # or once: npx rampa-cli check <url>
rampa doctor
rampa check https://example.com
```

Rampa checks pages against WCAG 2.2 A/AA. It reports what was checked and what was not, and it never says a page is accessible.

- **axe-core plus Rampa's own rules**, plus pixel checks and checks over the browser's accessibility tree.
- **Opt-in probes** that resize the page and press, click or type on it under a network guard.
- **Per-criterion judgment by a model**, local Gemma 4 12B through Ollama by default. Every claim must quote evidence that is on the page.
- **An opt-in cognitive profile** (`--profile cognitive`) with experimental advisories drawn from W3C COGA and GAIA.
- **Outputs and integrations:** SARIF, Markdown, HTML and JSON reports, a GitHub Action (`uses: guilhermebsantiago/rampa-cli@v0.1.0`), an MCP server, Playwright and Puppeteer helpers, and a library API.

How it measures against axe-core, Pa11y, IBM Equal Access, Siteimprove Alfa and QualWeb, with its caveats, is in [How it compares](https://github.com/guilhermebsantiago/rampa-cli#how-it-compares) and [docs/benchmark.md](https://github.com/guilhermebsantiago/rampa-cli/blob/main/docs/benchmark.md). Experimental checks report below the default confidence threshold until they pass the evaluation gate.
